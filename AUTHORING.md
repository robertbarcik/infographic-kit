# Authoring guide: sketchnote pages

> Generated by `node engine/list.mjs --authoring` from `engine/authoring.template.md`
> and the engine code. Do not edit `AUTHORING.md` by hand.

You write **content only**: a JSON spec in `specs/<name>.json`. The engine decides every
colour, size, font, position, outline and picture. Same spec in, same pixels out.

```
node engine/render.mjs specs/<name>.json    # render + measure one page
node engine/render.mjs --all                # every spec in specs/ (files starting with _ are skipped)
node engine/list.mjs                        # components, budgets, icons, roles (from the code)
```

Output: `out/<name>.png` (2480x3508), `out/<name>.pdf` (A4, 1 page), `out/<name>.html`,
`out/<name>.report.json`. Exit code 1 = the page is not acceptable; read the messages, fix
the **spec**, render again. Always open the PNG and look at it.

## 1. Content rules (every page)

1. One page = one idea. The title says the idea, not only the topic ("Protocols: agreed rules").
2. An everyday analogy carries the page (top section, usually `dialogue`), and the technical
   part maps back to it explicitly (the analogy's rules reappear as the key ideas).
3. A beginner can follow it; a practitioner still learns a precise fact: real commands,
   port numbers, real tool names in the examples.
4. Short, spoken sentences. No filler, no marketing tone, no "leverage / seamless / robust".
5. Every fact must be true. Simplify, never falsify. Use documentation values
   (`example.com`, `203.0.113.10`) rather than invented "real" ones.
6. The last row holds the closing strip: `callout` with `"variant": "remember"`, one sentence.

## 2. Spec skeleton

```json
{
  "title": { "number": "10", "text": "Protocols: agreed rules", "subtitle": "optional second line" },
  "rows": [
    { "sections": [ { "component": "dialogue", "label": "A conversation analogy", "...": "..." } ] },
    { "sections": [ { "component": "callout", "variant": "key", "text": "One key sentence." } ] },
    { "ratio": [5, 4], "sections": [ { "component": "layer-stack", "...": "..." }, { "component": "key-ideas", "...": "..." } ] },
    { "ratio": [3, 2], "sections": [ { "component": "exchange", "...": "..." }, { "stack": [ { "component": "definitions", "...": "..." }, { "component": "illustration", "...": "..." } ] } ] },
    { "sections": [ { "component": "callout", "variant": "remember", "text": "The one sentence to keep." } ] }
  ]
}
```

- A page is a vertical stack of **rows**; a row holds 1-3 **sections** side by side,
  widths by `ratio` (whole numbers, e.g. `[3, 2]`; default equal).
- A cell may be `{ "stack": [section, section(, section)] }`: 2-3 sections stacked
  vertically in one column (for "one tall section left, two small ones right").
- Every section: `component` (required), `label` (the tab; most components require it),
  `role` (optional semantic colour), plus the component's own fields below.
- Optional top-level `meta`: `{ "lang": "sk", "author": "...", "source": "...", "notes": "..." }`
  and `$comment` (ignored).

```text
title:
  number: text <= 4 chars (optional) - page number, e.g. "10"
  text: text <= 46 chars - the idea of the page, not only the topic
  subtitle: text <= 52 chars (optional)
section (every section):
  component: text <= 20 chars
  label: text <= 44 chars (optional) - section label tab (shown in capitals)
  role: role (optional) - semantic colour
rows: 2-7; sections per row: 1-3; sections per page: <= 12; ratio: one whole number 1-5 per section
```

**Forbidden anywhere in a spec:** colours, sizes, coordinates, fonts, CSS, raw HTML/SVG.
Keys such as `color`, `style`, `class`, `html`, `svg`, `font`, `size`, `width`, `height`,
`x`, `y`, `left`, `top`, `margin`, `padding`, `background`, `fill`, `stroke` are rejected.
If a page needs something the engine cannot draw, the fix is a new engine component or icon,
never a hack in the spec.

## 3. Text

- Inline markup only: `**bold**`, `` `code` ``, `->` (drawn arrow), and `\n` for a line
  break where a field allows 2 lines. `code` keeps its case even in capitalised labels and
  headings, and wraps only after spaces and `/ . ? & = , _` (never inside a flag like `-d`).
  A real command of more than a few words belongs in the `command` component, not in bullets.
- Bold is drawn with a thin outline so it shows in the handwriting font in every component.
- Budgets below are **maximum visible characters** (markup not counted). Staying well under
  them keeps the page airy. The layout check still fails a page if text does not fit the
  actual box (e.g. many cards in a narrow column), so budgets are necessary, not sufficient.
- Characters: Latin incl. all Slovak/Czech diacritics (ľ š č ť ž ý á í é ú ä ô ň ď ŕ ĺ),
  common punctuation, en dash. No emoji, no symbols outside Latin; write `->` for an arrow.

## 4. Roles (semantic colour)

- `info`: blue - explanation, definitions, neutral technical content
- `concept`: green - the key idea, the correct way, success
- `example`: yellow - examples, analogies, "for instance"
- `action`: orange - steps, actions, processes
- `accent`: rose - a soft highlight (NOT a warning)
- `detail`: purple - extra detail, side notes, deeper facts
- `warning`: red - RESERVED for warnings, pitfalls and the REMEMBER strip
- `neutral`: grey - plain containers

Items inside components (cards, layers, terms, steps) cycle through pastel roles
automatically; set `role` on an item only when the colour must mean something.

## 5. Components

### `callout` (alias: `goal`)
icon + bold lead word + sentence: goal, remember strip, tip, key sentence, habit with bullets

```text
  label: optional, default role: info
    variant: goal | remember | key | tip | note (default note) (optional) - goal | remember (red, closing strip) | key (centred key sentence, no icon) | tip | note
    lead: text <= 22 chars (optional) - bold lead word; defaults: "Goal:", "Remember:", "Tip:"
    text: text <= 170 chars
    icon: icon name (optional) - defaults by variant (target, warning, lightbulb, info)
    bullets: list of 1-5 (optional), each: text <= 64 chars
```

Example:

```json
{"component":"callout","variant":"remember","text":"Protocols are agreements. Without them, devices could not understand each other."}
```

### `dialogue`
the everyday analogy: two people with speech bubbles (one line each, or 2-4 numbered turns) and a centred box of rules

```text
  label: required, default role: info
    a: { - person on the left
        name: text <= 18 chars
        says: text <= 42 chars (optional) - one line of speech; omit when using "turns"
        look: { (optional) - appearance of the person (all optional enums)
            hair: short | long | curly | bun | bald (optional)
            hairTone: dark | brown | blonde | red | grey (optional)
            skin: light | medium | tan | dark (optional)
            shirt: info | concept | example | action | accent | detail | warning | neutral (optional)
            expression: happy | smile | neutral | surprised | thinking (optional)
            pose: neutral | pointing | thinking (optional)
            facing: right | left (optional)
            holding: icon name (optional) - a prop held in one hand, any icon name (e.g. passport, cloche, envelope); not with "thinking"
          }
      }
    b: { - person on the right
        name: text <= 18 chars
        says: text <= 42 chars (optional) - one line of speech; omit when using "turns"
        look: { (optional) - appearance of the person (all optional enums)
            hair: short | long | curly | bun | bald (optional)
            hairTone: dark | brown | blonde | red | grey (optional)
            skin: light | medium | tan | dark (optional)
            shirt: info | concept | example | action | accent | detail | warning | neutral (optional)
            expression: happy | smile | neutral | surprised | thinking (optional)
            pose: neutral | pointing | thinking (optional)
            facing: right | left (optional)
            holding: icon name (optional) - a prop held in one hand, any icon name (e.g. passport, cloche, envelope); not with "thinking"
          }
      }
    turns: list of 2-4 (optional) - a short exchange instead of a.says/b.says; shown as numbered bubbles in order, each: {
            who: a | b
            says: text <= 42 chars
          }
    intro: text <= 70 chars (optional) - sentence directly above the rules box
    rules: list of 2-5 - what the two people implicitly agree on, each: text <= 52 chars
```

Example:

```json
{"label":"A conversation analogy","component":"dialogue","a":{"name":"Person A","says":"Shall we meet at 3 pm?"},"b":{"name":"Person B","says":"Yes, at 3 pm!"},"intro":"We both understand because we agree on rules:","rules":["use the same language (syntax)","take turns in the right order (order)"]}
```

### `exchange` (alias: `scene`)
who sends what to whom: 2-4 actors (icons or drawn people with speech bubbles) in a row with labelled arrows between neighbours; 1-3 stacked numbered scenarios. "scene" is the same component.

```text
  label: required, default role: concept
    scenarios: list of 1-3, each: {
            title: text <= 40 chars (optional) - scenario heading; numbered automatically when there are 2-3 scenarios
            role: role (optional) - default cycles yellow, blue, rose
            a: { (optional) - classic form: left actor
                icon: icon name, or [icon, icon] for a combined picture (optional) - one icon, or two (e.g. ["laptop","database"]) drawn as one picture; use icon OR person
                person: { (optional) - draw a person instead of an icon; {} for the default look, or look enums
                    hair: short | long | curly | bun | bald (optional)
                    hairTone: dark | brown | blonde | red | grey (optional)
                    skin: light | medium | tan | dark (optional)
                    shirt: info | concept | example | action | accent | detail | warning | neutral (optional)
                    expression: happy | smile | neutral | surprised | thinking (optional)
                    pose: neutral | pointing | thinking (optional)
                    facing: right | left (optional)
                    holding: icon name (optional) - a prop held in one hand, any icon name (e.g. passport, cloche, envelope); not with "thinking"
                  }
                says: text <= 40 chars (optional) - speech bubble above a person (person actors only)
                name: text <= 20 chars - e.g. "Laptop", "Sender"
                tag: text <= 12 chars (optional) - role tag pill, e.g. "CLIENT"
                tagRole: role (optional) - colour meaning of the tag; default: first actor yellow, others blue
                caption: text <= 46 chars, <= 2 lines (optional) - process / software / what it does, e.g. "Web browser\n(e.g. Chrome)"
              }
            b: { (optional) - classic form: right actor
                icon: icon name, or [icon, icon] for a combined picture (optional) - one icon, or two (e.g. ["laptop","database"]) drawn as one picture; use icon OR person
                person: { (optional) - draw a person instead of an icon; {} for the default look, or look enums
                    hair: short | long | curly | bun | bald (optional)
                    hairTone: dark | brown | blonde | red | grey (optional)
                    skin: light | medium | tan | dark (optional)
                    shirt: info | concept | example | action | accent | detail | warning | neutral (optional)
                    expression: happy | smile | neutral | surprised | thinking (optional)
                    pose: neutral | pointing | thinking (optional)
                    facing: right | left (optional)
                    holding: icon name (optional) - a prop held in one hand, any icon name (e.g. passport, cloche, envelope); not with "thinking"
                  }
                says: text <= 40 chars (optional) - speech bubble above a person (person actors only)
                name: text <= 20 chars - e.g. "Laptop", "Sender"
                tag: text <= 12 chars (optional) - role tag pill, e.g. "CLIENT"
                tagRole: role (optional) - colour meaning of the tag; default: first actor yellow, others blue
                caption: text <= 46 chars, <= 2 lines (optional) - process / software / what it does, e.g. "Web browser\n(e.g. Chrome)"
              }
            arrows: list of 1-4 (optional) - classic form: arrows between a and b, each: {
                    dir: right | left (optional) - right = towards the next actor, left = back; omit for a plain note line
                    kind: request | response | neutral (optional) - arrow colour meaning; default right=request, left=response
                    line: solid | dashed (default solid) (optional)
                    label: text <= 40 chars, <= 2 lines (optional)
                    step: text <= 2 chars (optional) - number badge drawn on the arrow, e.g. "1"
                  }
            actors: list of 2-4 (optional) - scene form: 2-4 actors left to right, each: {
                    icon: icon name, or [icon, icon] for a combined picture (optional) - one icon, or two (e.g. ["laptop","database"]) drawn as one picture; use icon OR person
                    person: { (optional) - draw a person instead of an icon; {} for the default look, or look enums
                        hair: short | long | curly | bun | bald (optional)
                        hairTone: dark | brown | blonde | red | grey (optional)
                        skin: light | medium | tan | dark (optional)
                        shirt: info | concept | example | action | accent | detail | warning | neutral (optional)
                        expression: happy | smile | neutral | surprised | thinking (optional)
                        pose: neutral | pointing | thinking (optional)
                        facing: right | left (optional)
                        holding: icon name (optional) - a prop held in one hand, any icon name (e.g. passport, cloche, envelope); not with "thinking"
                      }
                    says: text <= 40 chars (optional) - speech bubble above a person (person actors only)
                    name: text <= 20 chars - e.g. "Laptop", "Sender"
                    tag: text <= 12 chars (optional) - role tag pill, e.g. "CLIENT"
                    tagRole: role (optional) - colour meaning of the tag; default: first actor yellow, others blue
                    caption: text <= 46 chars, <= 2 lines (optional) - process / software / what it does, e.g. "Web browser\n(e.g. Chrome)"
                  }
            links: list of 1-3 (optional) - scene form: one entry per gap between neighbouring actors (actors - 1); each has arrows OR versus, each: {
                    arrows: list of 1-3 (optional), each: {
                            dir: right | left (optional) - right = towards the next actor, left = back; omit for a plain note line
                            kind: request | response | neutral (optional) - arrow colour meaning; default right=request, left=response

                  }
          }
```

Example:

```json
{"label":"Who asks, who answers","component":"exchange","scenarios":[{"a":{"icon":"laptop","name":"Laptop","tag":"CLIENT","caption":"Web browser"},"b":{"icon":"server","name":"Web server","tag":"SERVER","caption":"nginx"},"arrows":[{"dir":"right","label":"Request:\nGET /index.html"},{"dir":"left","label":"Response:\nweb page (HTML)"}]}]}
```

Example (second form):

```json
{"label":"A registered letter","component":"scene","scenarios":[{"actors":[{"person":{},"says":"Registered, please.","name":"Sender"},{"icon":"stamp","name":"Post office","caption":"records the letter"},{"person":{"hair":"long"},"says":"Signed, received.","name":"Recipient"}],"links":[{"arrows":[{"dir":"right","label":"letter"}]},{"arrows":[{"dir":"right","label":"delivery"},{"dir":"left","line":"dashed","label":"signed receipt"}]}]}]}
```

### `layer-stack`
coloured stacked layers (top to bottom), one description per layer, side axis label, optional bracket over a range of layers

```text
  label: required, default role: info
    layers: list of 2-7 - top layer first, each: {
            name: text <= 14 chars
            text: text <= 64 chars, <= 2 lines
            role: role (optional) - default cycles rose, yellow, green, blue, purple
          }
    axis: { (optional) - labels at the upper and lower end of the side arrow
        upper: text <= 36 chars (optional)
        lower: text <= 36 chars (optional)
      }
    bracket: { (optional) - a bracket on the right over a range of layers, e.g. "each VM repeats these"
        from: text <= 14 chars - name of the first layer in the range
        to: text <= 14 chars - name of the last layer
        label: text <= 40 chars
      }
```

Example:

```json
{"label":"A layered protocol stack","component":"layer-stack","axis":{"upper":"Higher layers (closer to users)","lower":"Lower layers (closer to hardware)"},"layers":[{"name":"Application","text":"network applications (e.g. HTTP, DNS)"},{"name":"Transport","text":"end-to-end communication (e.g. TCP, UDP)"}],"bracket":{"from":"Application","to":"Transport","label":"in the operating system and apps"}}
```

### `card-grid`
N small cards (2-10) in one or two rows: heading, sub-tag, icon, text; "compact" puts the icon beside the heading for many small cards

```text
  label: required, default role: info
    variant: normal | compact (default normal) (optional) - compact: icon beside the heading, less height per card (good for 7-10 cards)
    items: list of 2-10, each: {
            heading: text <= 16 chars
            tag: text <= 22 chars (optional) - small sub-tag under the heading, e.g. "(link layer)"
            icon: icon name
            text: text <= 84 chars
            role: role (optional) - default cycles purple, green, yellow, rose, blue, orange
          }
```

Example:

```json
{"label":"Examples of common protocols","component":"card-grid","items":[{"heading":"TCP","tag":"(transport layer)","icon":"arrows-lr","text":"Reliable, ordered delivery."},{"heading":"DNS","tag":"(application layer)","icon":"globe","text":"Translates names to IP addresses."}]}
```

    b: { - right column

### `illustration`
picture from icons + arrows: hub (centre + satellites by side), fan (asker -> hub -> numbered targets), row; two-way and numbered edges, optional legend

```text
  label: required, default role: accent
    layout: hub | fan | row (default hub) (optional) - hub: nodes[0] centre; fan: nodes[0] asker left, nodes[1] hub, rest fanned right top-to-bottom; row: left to right
    nodes: list of 2-6, each: {
            id: text <= 16 chars - short id used by edges (letters, digits, -)
            icon: icon name
            label: text <= 30 chars, <= 2 lines (optional)
            side: left | right | top | bottom (optional) - hub only: where this satellite sits (default alternates left, right)
          }
    edges: list of 1-6 (optional), each: {
            from: text <= 16 chars
            to: text <= 16 chars
            label: text <= 18 chars (optional) - placed by the engine clear of arrows and labels
            kind: request | response | neutral (optional) - colour meaning (default: request if "back" is given, else neutral)
            line: solid | dashed (default solid) (optional)
            back: text <= 18 chars (optional) - draws a second arrow back along the same edge (a response), with this label
            step: text <= 2 chars (optional) - number badge, e.g. "1"; placed near the start, clear of the arrowhead
          }
    legend: list of 1-3 (optional) - tiny key explaining the arrow styles, each: {
            kind: request | response | neutral
            line: solid | dashed (default solid) (optional)
            text: text <= 28 chars
          }
    text: text <= 200 chars (optional) - explanation under the picture
```

Example:

```json
{"label":"Who does the walking","component":"illustration","layout":"fan","nodes":[{"id":"laptop","icon":"laptop","label":"Your laptop"},{"id":"resolver","icon":"server-rack","label":"Resolver"},{"id":"root","icon":"globe","label":"Root"},{"id":"tld","icon":"address-book","label":".com TLD"},{"id":"auth","icon":"server","label":"Authoritative"}],"edges":[{"from":"laptop","to":"resolver","label":"name?","back":"address"},{"from":"resolver","to":"root","step":"1","back":"ask .com"},{"from":"resolver","to":"tld","step":"2"},{"from":"resolver","to":"auth","step":"3"}]}
```

terminal strip(s): a real command on 1-4 lines, optional output line, one-line explanation

  label: required, default role: action

### `commit-graph` (alias: `track-graph`)
lanes (1-3) with dots in time order; forks and joins by naming parents; branch tags and HEAD point at dots

```text
  label: required, default role: info
    lanes: list of 1-3 - top lane first, each: {
            id: text <= 16 chars
            name: text <= 16 chars
            role: role (optional) - default: blue, purple, orange
          }
    commits: list of 2-9 - in time order, left to right, each: {
            id: text <= 12 chars - short id used by parents/tags, e.g. "c3"
            lane: text <= 16 chars - lane id
            label: text <= 18 chars, <= 2 lines (optional) - shown under the dot, e.g. "a3f9c soup"
            parents: list of 0-2 (optional) - default: the previous dot on the same lane; two parents = merge, each: text <= 12 chars
          }
    tags: list of 1-4 (optional) - branch names pointing at a commit, each: {
            name: text <= 16 chars
            at: text <= 12 chars - commit id
            was: text <= 12 chars (optional) - commit id where this pointer was before (drawn as a dashed ghost with an arrow to its new place, e.g. a fast-forward)
            role: role (optional)
          }
    head: text <= 16 chars (optional) - the tag name (or commit id) HEAD points at
    arrows: none | to-parent (default none) (optional) - to-parent: arrowheads point from each dot back to its parent, as Git stores it
    text: text <= 180 chars (optional) - explanation under the graph
```

Example:

```json
{"label":"Branch and merge","component":"commit-graph","lanes":[{"id":"main","name":"main"},{"id":"feat","name":"feature"}],"commits":[{"id":"c1","lane":"main","label":"a1 start"},{"id":"c2","lane":"feat","label":"b2 chili","parents":["c1"]},{"id":"c3","lane":"main","label":"a3 salt"},{"id":"c4","lane":"main","label":"m4 merge","parents":["c3","c2"]}],"tags":[{"name":"main","at":"c4"},{"name":"feature","at":"c2"}],"head":"main"}
```

## 7. People (dialogue)

`a.look` / `b.look` (dialogue) and `person` (scene actors) pick from these enums; defaults:
A = short dark hair, green shirt; B = long brown hair, purple shirt; both standing. Vary them
across pages so the cast does not repeat.

- `hair`: short | long | curly | bun | bald (default `short`)
- `hairTone`: dark | brown | blonde | red | grey (default `dark`)
- `skin`: light | medium | tan | dark (default `light`)
- `shirt`: info | concept | example | action | accent | detail | warning | neutral (default `concept`)
- `expression`: happy | smile | neutral | surprised | thinking (default `happy`)
- `pose`: neutral | pointing | thinking (default `neutral`)
- `facing`: right | left (default `right`)
- `holding`: any icon name; the person holds it up in one hand (passport, cloche,
  envelope, postcard, bookmark, key...). Not with `pose: "thinking"`.
- Speech bubbles: every bubble has a tail pointing at its speaker, steered around raised
  hands, props and other bubbles, and its outline takes the speaker's shirt colour, so who
  says what is clear at a glance. In a multi-turn dialogue (`turns`) the conversation sits
  between the two people and the intro + rules run full width underneath; the people grow at
  most 1.15x to match the conversation.

## 8. What the validator checks (the meter)

Before rendering (spec errors, nothing is drawn):
schema (unknown component / key / icon / role / enum value, missing field, wrong type),
forbidden styling keys, raw HTML, text budgets, list lengths, max rows/sections, the
remember strip in the last row, characters the fonts cannot draw, cross-field rules
(e.g. illustration edges must name existing nodes).

After layout (the page is rendered, then measured):

| code | meaning | typical fix |
|---|---|---|
| `page-overflow` | content taller than the page at type scale 1.0; the message says how many px and about how many lines to cut, and names the tallest rows | cut text or items; move a section to another page (see section 10) |
| `page-underfilled` | > 8 % of the page empty at the largest type scale and spacing cap; boxes are never inflated to fill | add content: a section, an example, a key sentence |
| `clipped` | a text/box sticks out of its container | shorten the text; widen the section (`ratio`) |
| `text-overflow` | a word or `code` cannot wrap and is wider than its box | shorten the code / URL, break it into words |
| `overlap` | two boxes/texts in the same container overlap | report as an engine bug if the spec is valid |
| `arrow-over-text` | a drawn arrow crosses a text | shorten labels; change illustration layout |
| `outside-page` | something lies outside the page | engine bug |
| `font-too-small` | text below 17 px | engine bug (the engine never goes below 17 px) |
| `missing-glyph` | the font has no glyph for a character | replace the character |
| `tail-over-person` | a speech-bubble tail touches a raised arm, hand or prop, or another person | shorten that bubble, change the pose, or move the prop |
| `tail-over-bubble` | a tail crosses another bubble | fewer or shorter turns |
| `tail-wrong-speaker` | a tail ends nearer to another person than to its speaker | engine bug if the spec is valid |
| `tail-too-short` | a tail is shorter than 14 px | engine bug |
| `bubble-over-person` | a bubble touches a person's head, arm, hand or prop | shorter bubble text, or no prop |
| `unbalanced-row` (warning) | one section in a row is much shorter than its neighbour | balance content or change `ratio` |
| `lucide-fallback` (warning) | a `lucide:` icon is used | fine for small details; request a kit icon for anything prominent |

Auto-fit: the engine scales all type, icons and spacing (`k` 1.0-1.4, body text 19-27 px,
smallest text at least 17 px), then stretches vertical gaps a little (`vs` 1-1.3). Callouts (goal, tip, remember, key)
always hug their content; the small remainder goes to rows with real content. A page that
still cannot be filled fails as `page-underfilled`. The report shows `k`, `vs`, body size
and empty space.

## 9. Picking the analogy component

- `dialogue`: two people talk (one line each, or 2-4 numbered `turns`) and a rules box
  names what they agree on. Best for "agreement / conversation" analogies.
- `scene` (= `exchange` with `actors`/`links`): a picture story of 2-4 actors in a row,
  each a drawn person (optional speech bubble) or an icon, with labelled arrows between
  neighbours. Best for "something travels from A via B to C" analogies (letter, waiter,
  phone book). Stack 2-3 scenarios to contrast (registered letter vs postcard).
- `exchange` classic form (`a`, `b`, `arrows`): the technical mapping, device to device.
- A person can carry the thing that travels (`holding`: passport, cloche, envelope...), so
  the analogy object is visible in the picture without an extra actor.
- Scene arrows take `step` badges (order of events) instead of "1." in the label text; a
  link `{ "versus": "or" }` draws a divider between two alternatives instead of an arrow.
- Technical pictures after the analogy: `illustration` `fan` for "one asks, the hub calls
  several in order" (DNS resolver: numbered `step` badges, `back` answers), `hub` with `side`
  for "one thing, many roles around it", `commit-graph` for history with branches.

## 10. Page capacity (plan before you write)

Measured at the smallest type scale (k = 1.0), full page width unless a width is given.
The page body is **1698 px**; the title takes about **75 px** (about **117 px** with a
subtitle); every row adds a **15 px** gap. Sections in one row take the height of the
tallest.

| section | typical height |
|---|---|
| callout, one line (goal, tip, remember) | 90-100 px |
| callout `key` (one sentence) | 50 px |
| callout with 2-4 bullets (half width) | 180-210 px |
| `dialogue`, one line each + 4 rules | 340 px |
| `dialogue` with 4 `turns` + 4 rules | 410-455 px |
| `exchange` / `scene`, 1 scenario | 260-300 px |
| `exchange` / `scene`, 2 stacked scenarios | 570-610 px |
| `exchange`, 3 stacked scenarios (60 % width) | 770 px |
| `steps`, 4-5 steps | 210-250 px |
| `card-grid`, 6 cards in one row | 270 px |
| `card-grid`, 7-8 cards (two rows) | 400 px |
| `card-grid` `compact`, 10 cards | 300 px |
| `key-ideas`, 3-4 cards (half width) | 330-420 px |
| `layer-stack`, 4-5 layers (half width) | 340-355 px |
| `compare`, 3-5 rows | 235-320 px |
| `definitions`, 4 terms (60 % width) | 240-260 px |
| `illustration` with a caption (half width) | 250-345 px |
| `bullets` / `command`, 3-4 items (half width) | 160-300 px |
| `commit-graph`, 2 lanes | 230-280 px |

Rules of thumb:
- A page holds about **1500 px of sections** (6 rows including the remember strip).
- The reference shape fits: analogy (350-450) + key sentence (50) + a two-column row (350-420)
  + a full-width row (250-300) + a half/half row (200-300) + remember (100).
- Two stacked-scenario analogies, or a 4-turn dialogue plus a 3-scenario exchange, do not fit
  on one page. Split the topic, or pick the lighter form.
- Commands: one `command` section is one terminal window, whatever the number of commands;
  `output` keeps its line breaks (up to 3 lines). Code of 24 characters or less never breaks.
- `commit-graph`: put `main` on the top lane; a tag's `was` shows where the pointer stood
  before (fast-forward).
- `layer-stack` `bracket` in a half-width section: the label goes above the bracket (range
  starts at the top layer) or below it (range ends at the bottom layer).
- If `page-overflow` asks for N lines, cutting one card row, one scenario or one bullet list
  is usually faster than trimming words everywhere.
